# The Rule I Want for K-OS

Nothing should enter K-OS unless it belongs to one of these:

|Type|Destination|
|---|---|
|Permanent concept|Knowledge|
|Active work|Projects|
|Reusable process|Systems|
|Raw reference|Resources|
|Personal direction|Identity|
|Finished work|Archive|

Everything has one home.

# What I'll Do Differently

Instead of waiting for you to ask:

> "Where should I put this?"

I'll actively classify things.

For example:

If you ask about **Randles circuits**, I'll say:

- **Knowledge:** Electrochemical impedance, Randles circuit, battery modeling.
- **Project links:** LS-DYNA battery model (if relevant).
- **Systems:** None.

If you share a new heat sink test:

- **Project:** Heat Sink Gen-3.
- **Knowledge extracted:** Thermal resistance, time constant, fan performance (if new insights emerge).

That keeps the vault clean without interrupting your workflow.

# One More Improvement

I want to add something that wasn't in the original video's idea.

Every note we create should answer three questions:

```
Why does this exist?↓How is it connected?↓Where will I use it?
```

That prevents "orphan notes"—the biggest problem in most knowledge systems.
