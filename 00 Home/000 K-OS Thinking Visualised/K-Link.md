# K-OS Protocol v1.0

Whenever you start a message with:

```
K:
```

I will automatically switch into **K-OS Mode**.

That means I will **not** just answer your question. I'll think like your Systems Architect.

---

## What changes when you use `K:`?

Instead of only answering, I'll also ask myself:

✅ Is this reusable knowledge?

✅ Where should it live in K-OS?

✅ What existing notes should it connect to?

✅ Is this a new concept or part of an existing one?

✅ Is this an observation, principle, workflow, or project?

✅ What future questions does this create?

✅ How can this be visualized?

✅ Does this deserve a permanent place?

---

## Example

Instead of

> Explain transient thermal analysis.

you'll write

```
K:Teach me transient thermal analysis from first principles.
```

Now I'll give you:

- Deep explanation
- K-OS note structure
- Internal links
- Related concepts
- Suggested diagrams
- Future learning path
- Knowledge maturity
- Engineering applications
- Questions to think about

Everything ready to enter K-OS.

---

# Another important rule

**`K:` does NOT mean "save everything."**

It means:

> **"This conversation is intended to produce knowledge suitable for K-OS."**

Sometimes, after discussion, we may conclude:

> ❌ This isn't reusable enough.

And that's okay. We won't force every K: conversation into the vault.

# One small improvement I'd like to add

I propose we reserve **`K!`** (with an exclamation mark) for a special case.

### #K-link-1:  `K:`

> Build or extract knowledge.

### #K-Link-2 `K!`

> **This is critical knowledge that should become a polished, evergreen note.**

For example:

```
K!Create the definitive note on Thermal Resistance.
```

That tells me:

- Spend extra effort.
- Make it high quality.
- This is a long-term reference, not just today's discussion.
